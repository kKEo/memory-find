## What the numbers say

- **Chunking reached the tail.** All three `long-document` queries, whose marker sits in the last section past where the journal's 1,500-rune cap used to stop, are found at rank 1 and the first hit comes through the semantic arm as well as the keyword arm (`first hit via` column). The journal-era harness could not tell which arm found them.
- **Stemming works but ranking within the stem cluster is loose.** The stemming query now has three relevant documents; all three are in the top 10 (recall@10 = 1.00) but only one is in the top 1 and two in the top 5. With the hash embedder, which has no notion of morphology, the semantic arm cannot help here; this is a P3 item for the real model.
- **Abstention is real.** Both no-match queries return the structured abstention (zero results with a reason and a hint) because semantic-only candidates below the 0.30 similarity floor are dropped. The floor is the weak band; P3 calibrates it per model.
- **Recency is the weakest category.** The two-version rate-limit pair ranks the newer fact first only half the time at rank 1. Both are labelled relevant, so this says more about the fixture than the ranking; P4's supersession chain turns it into a real knowledge-update test.
- **Latency** is not reported here because the hash embedder is instant; the real-model numbers live in `docs/spikes/S4-embedding-models.md` and in the P2 smoke run (see the article).

## How to read a miss

`go test ./internal/eval/ -run TestRetrievalEval -v` prints this table with the arms that produced each first hit. For one query, `memo-mcp explain "<query>" <memo://uri>` prints the full `Why` block (per-arm rank, raw score and contribution, recency factor, provenance). The `memo-mcp eval` subcommand with `--explain-failures` is a P3 deliverable.
